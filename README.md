# ETL-пайплайн для обработки данных онлайн-университета

## О проекте

Итоговый проект по изучению Python.

В рамках проекта реализован ETL-пайплайн для получения данных
корпоративного клиента через API, их обработки и загрузки
в локальную базу данных PostgreSQL.

Проект также включает логирование этапов обработки данных
и обработку возникающих ошибок.

## Задача проекта

Необходимо реализовать ETL-пайплайн, который:

1. Получает данные корпоративного клиента через API.
2. Обрабатывает и подготавливает полученные данные к загрузке.
3. Загружает обработанные данные в локальную базу данных PostgreSQL.
4. Ведёт лог работы скрипта с информацией об этапах обработки
   и возникающих ошибках.

## Этапы ETL-пайплайна

### 1. Получение данных

Проект обращается к API и получает данные за указанный период.

По умолчанию обрабатываются данные за предыдущий день. Также можно
передать произвольный период с помощью аргументов `--start` и `--end`.

При временных ошибках сервера или проблемах с запросом предусмотрены
повторные попытки получения данных.

### 2. Валидация данных

Полученные данные проходят проверку перед дальнейшей обработкой.

Проверяется:

- структура ответа API;
- наличие обязательных полей;
- типы и значения данных;
- содержимое `passback_params`;
- корректность типа попытки (`run` или `submit`);
- соответствие `is_correct` типу попытки;
- формат даты и времени.

Параметры LTI, содержащиеся в `passback_params`, извлекаются в
отдельные поля.

### 3. Преобразование данных

После валидации данные преобразуются к формату, необходимому
для загрузки в PostgreSQL.

В частности:

- `lti_user_id` преобразуется в поле `user_id`;
- дата и время преобразуются из строки в объект `datetime`.

### 4. Формирование агрегированного отчёта

На основе обработанных данных формируется агрегированный отчёт.

В отчёт входят:

- общее количество попыток (`total_attempts`);
- количество запусков кода (`run_attempts`);
- количество отправленных решений (`submit_attempts`);
- количество успешных решений (`successful_submits`);
- количество неуспешных решений (`failed_submits`);
- количество уникальных пользователей (`unique_users`);
- процент успешных решений (`success_rate`).

### 5. Загрузка в PostgreSQL

Преобразованные данные загружаются в таблицу `code_attempts`
локальной базы данных PostgreSQL.

При ошибке отдельной записи используется `SAVEPOINT`, поэтому ошибка
одной записи не приводит к откату уже обработанных записей.

### 6. Передача агрегированного отчёта

После завершения загрузки данных в PostgreSQL агрегированный отчёт
передаётся во внешние сервисы:

- [Google Sheets — результаты ETL](https://docs.google.com/spreadsheets/d/1R9rf82SZzekYtCUcLI3sh_YGspsWkAeI2wruYAuYfOM/edit?usp=sharing);
- электронная почта.
Ошибки при работе с внешними сервисами записываются в лог.

## Структура проекта
```text
online_university_etl/
│
├── main.py                  # Точка входа в ETL-пайплайн

├── database.py              # Подключение к PostgreSQL
├── loader.py                # Загрузка данных в PostgreSQL
├── google_sheets.py         # Загрузка отчёта в Google Sheets
├── email_sender.py          # Отправка отчёта по электронной почте

├── schema.sql               # SQL-схема таблицы PostgreSQL

├── .gitignore               # Файлы и каталоги, исключённые из Git
│
├── credentials/             # Учётные данные для Google API
└── logs/                    # Файлы логов
```

## Используемые технологии

- **Python** — основной язык программирования.
- **Requests** — получение данных через REST API.
- **PostgreSQL** — хранение обработанных данных.
- **psycopg2-binary (psycopg2)** — подключение Python к PostgreSQL.
- **python-dotenv** — загрузка переменных окружения из `.env`.
- **gspread** — работа с Google Sheets.
- **logging** — ведение логов работы ETL-пайплайна.
- **smtplib** и **EmailMessage** — отправка отчётов по электронной почте.

## Настройка проекта

Для запуска проекта необходимо:

1. Установить Python.
2. Установить зависимости проекта.
3. Настроить переменные окружения.
4. Создать базу данных PostgreSQL и выполнить SQL-скрипт `schema.sql`.
5. Настроить доступ к Google Sheets.
6. Настроить параметры SMTP для отправки email.

### Установка зависимостей

Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте виртуальное окружение в Windows:

```bash
.venv\Scripts\activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

### Настройка переменных окружения

Создайте файл `.env` в корневой директории проекта на основе файла
`.env.example`.

В `.env` необходимо указать ключ доступа к API, пароль PostgreSQL и 
параметры SMTP-сервера:

```text
CLIENT_KEY=
DB_PASSWORD=
SMTP_SERVER=
SMTP_PORT=465
EMAIL_SENDER=
EMAIL_PASSWORD=
EMAIL_RECIPIENT=
```

Файл `.env` содержит конфиденциальные данные и не должен добавляться
в Git-репозиторий.

### Настройка PostgreSQL

Создайте базу данных:

```text
online_university_etl
```

После создания базы данных выполните SQL-скрипт `schema.sql`.

Скрипт создаёт таблицу `code_attempts`, в которую загружаются
обработанные данные.

Подключение к базе данных осуществляется через модуль `database.py`.
Пароль пользователя PostgreSQL хранится в переменной окружения
`DB_PASSWORD`.

### Настройка Google Sheets

Для загрузки агрегированного отчёта необходимо настроить доступ
к Google Sheets API.

Файл учётных данных сервисного аккаунта необходимо разместить
по следующему пути:

```text
credentials/google_service_account.json
```

Идентификатор таблицы Google Sheets указывается в модуле
`google_sheets.py`.

Каталог `credentials/` исключён из Git-репозитория и не должен
содержать публичные учётные данные.

### Настройка отправки email

Для отправки агрегированного отчёта необходимо указать параметры
SMTP-сервера в файле `.env`:

```text
SMTP_SERVER=
SMTP_PORT=465
EMAIL_SENDER=
EMAIL_PASSWORD=
EMAIL_RECIPIENT=
```

Параметры используются модулем `email_sender.py` для подключения
к SMTP-серверу, авторизации и отправки отчёта по электронной почте.

## Запуск проекта

### Запуск за предыдущий день

Если аргументы `--start` и `--end` не указаны, проект автоматически
обрабатывает данные за предыдущий день.

Для запуска выполните:

```bash
python main.py
```

### Запуск за указанный период

Для обработки данных за конкретный период используются аргументы
`--start` и `--end`.

Пример:

```bash
python main.py --start "2026-08-01 00:00" --end "2026-08-01 23:59"
```

Дата и время должны быть указаны в формате:

```text
YYYY-MM-DD HH:MM
```

Аргументы `--start` и `--end` необходимо передавать одновременно.

## Результат работы

После завершения загрузки данных в PostgreSQL:

- обработанные данные загружаются в таблицу `code_attempts` базы
  данных PostgreSQL;
- формируется агрегированный отчёт за выбранный период;
- агрегированный отчёт загружается в Google Sheets;
- результаты обработки отправляются на электронную почту;
- информация о выполнении этапов и возникающих ошибках сохраняется
  в логах.

Пример агрегированного отчёта:

```text
Период: 2026-08-01 – 2026-08-14
Всего попыток: 3012
Запусков кода: 1736
Отправок решений: 1276
Успешных решений: 484
Неуспешных решений: 792
Уникальных пользователей: 56
Процент успешных решений: 37.93%
```

## Логирование и обработка ошибок

Во время работы ETL-пайплайна ведётся логирование основных этапов
обработки данных и возникающих ошибок.

Логи выводятся в консоль и одновременно сохраняются в текстовые файлы
в директории `logs/`.

Для каждого дня создаётся отдельный файл лога. При запуске проекта
удаляются файлы логов старше трёх дней.

Для разных типов ошибок предусмотрена соответствующая обработка:

- ошибки получения данных через API;
- некорректные данные, полученные от API;
- ошибки отдельных записей при загрузке в PostgreSQL;
- ошибки при отправке отчёта во внешние сервисы.

При ошибке отдельной записи во время загрузки в PostgreSQL используется
`SAVEPOINT`, что позволяет продолжить обработку остальных записей.

## Известные ограничения

- При повторном запуске проекта за один и тот же период записи могут
  быть загружены в PostgreSQL повторно, поскольку в текущей реализации
  не предусмотрен механизм защиты от дублирования данных.
- Для работы с Google Sheets необходим файл учётных данных сервисного
  аккаунта.
- Для отправки email необходимо корректно настроить SMTP-параметры.
- Проект рассчитан на локальный запуск.
